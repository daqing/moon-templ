# 在 MoonBit 中实现 templ 模板引擎 —— 可行性调研

调研日期:2026-10-16
调研对象:[a-h/templ](https://github.com/a-h/templ) v0.3.1070(Go 实现)
目标:在 MoonBit 中实现等价的模板引擎 `moon-templ`

---

## 0. 结论摘要

**可行,而且 MoonBit 提供了一条 Go 版本没有的"官方集成通道"。**

三条核心结论:

1. **架构路线已经确定:必须走外部 codegen,不能用宏。** MoonBit 只有 derive 宏(`derive(@json.ToJson)`),没有能承载 `<div>...</div>` 这种 HTML 优先 DSL 的通用语法宏。templ 的语法本身不是 MoonBit 表达式,宏阶段根本解析不了,所以 `pre-build` + 独立生成器是唯一路线 —— 而这恰好是 templ 自己的做法。

2. **MoonBit 有比 Go 更好的落地条件。** templ 依赖 Go 的 `go/parser` + `go/ast` 来解析模板里嵌的 Go 表达式(签名抽取、`if`/`for`/`switch` 条件校验)。MoonBit 没有等价物,但**不需要**:生成器把表达式原文抄进产物,交给 MoonBit 编译器做类型检查,反而更简单、更宽松。同时 MoonBit 的 `Logger` trait 天然对应 Go 的 `io.Writer`,`Show` trait 天然对应 templ 的"可字符串化"约束。

3. **工作量约 12k–15k 行 MoonBit**(对齐 templ 的 parser 5.8k + generator 8.2k + runtime 1.1k 行 Go)。MVP(组件、表达式、if/for/属性、children)约 4k–5k 行,2–4 周。

**最大的工程风险不是技术,是 DX:** MoonBit 的构建钩子(`rule`+`dev_build` 或 `pre-build`,两套等价)要求逐文件显式声明输入输出,不支持目录或 glob,而 templ 的 `templ generate .` 是零配置扫目录。缓解办法见 §3.4 与 §6。

## 1. templ 的实现规格

### 1.1 语法全集(实现时的权威依据)

templ 语言的唯一定义是 `parser/v2/types.go`(1581 行),不是 BNF。核心语法:

```templ
package main

import "github.com/a-h/templ"

// 组件:名字 + 参数,签名被逐字复制到函数头
templ hello(name string) {
	<div>Hello, { name }</div>
}

// 方法形式
templ (d Data) Method() { <div>{ d.Name }</div> }

// 泛型(签名透传,所以白嫖)
templ Script[T any](name string, data T) { <script id={ name }>{ data }</script> }
```

节点级分派顺序(`parser/v2/templateparser.go` 的 `templateNodeParsers`,顺序即优先级):

| # | 语法 | AST 节点 | 语义 |
|---|---|---|---|
| 1 | `<!doctype html>` | `DocType` | 大小写不敏感 |
| 2 | `<!-- ... -->` | `HTMLComment` | **输出**到 HTML,内容不得含 `--` |
| 3 | `// ...` / `/* */` | `GoComment` | **不输出** |
| 4 | `<style>` `<script>` | `RawElement` / `ScriptElement` | 内容完全不解析。**勘误**:templ 源码里这行的注释写的是 `<text>`,但注册的其实是 `parse.Any(styleElement, scriptElement)` —— `<text>` 与 `<>` 在 v0.3.1070 中并不存在(`elementNameParser` 也不接受空标签名),不要照注释实现 |
| 5 | `<name ...>` | `Element` | 元素名首字符 `[a-z]`,后续 `[a-z0-9-:]` |
| 6 | `if expr { } else if { } else { }` | `IfExpression` | `{` 后必须换行 |
| 7 | `for ... { }` | `ForExpression` | C 风格与 range 都支持 |
| 8 | `switch ... { case ...: }` | `SwitchExpression` | 含类型 switch |
| 9 | `{! expr }` | `CallTemplateExpression` | **已废弃**,等价 `@expr` |
| 10 | `@expr` `@expr { }` | `TemplElementExpression` | 组件调用;`@` 前必须有空白 |
| 11 | `{ children... }` | `ChildrenExpression` | 渲染子内容 |
| 12 | `{{ stmt }}` | `GoCode` | 原样写入函数体 |
| 13 | `{ expr }` | `StringExpression` | 转义输出 |
| 14 | `fallthrough` | `Fallthrough` | 仅 switch 内 |
| 15 | 其他文本 | `Text` | 兜底 |

**⚠️ 最容易踩的语义陷阱:`{! expr }` 不是"非转义输出"**,它是已废弃的组件调用语法(有诊断提示 `use @foo syntax instead`)。v2 里**根本不存在非转义字符串输出语法**,输出原始 HTML 只能用 `@templ.Raw("...")`。

属性解析优先级(`elementparser.go` 注册顺序,决定歧义归属):

```
1. { attrs... }                     spread
2. name?={ expr }                   布尔表达式属性
3. name={ expr } | name="c" | name='c' | name=unquoted
4. if expr { attrs } else { attrs } 条件属性
5. name                             裸布尔属性
6. name="..."                       常量属性(兜底)
```

属性名 charset:`[a-zA-Z:_@][a-zA-Z0-9:_.@*-]*`(允许 `@`、`*`、`.` 是为了 Alpine.js / htmx)。

### 1.2 三种属性值会被特殊处理

| 条件 | 生成 |
|---|---|
| `class` + 表达式 | `[]any{...}` → `templ.CSSClasses(...).String()`,常量值 join 消空白 |
| `style` + 表达式 | `templruntime.SanitizeStyleAttributeValues` |
| `a[href]` `link[href]` `form[action]` `object[data]` | `templ.JoinURLErrs` + `EscapeString`(URL 白名单) |
| 属性名以 `on` / `hx-on:` 开头 | 当 `templ.ComponentScript` 处理,写 `.Call` |
| 其他表达式属性 | `templ.ResolveAttributeValue` |

## 2. Go 特性 → MoonBit 映射(难点与方案)

| Go 侧依赖 | templ 用途 | MoonBit 方案 | 风险 |
|---|---|---|---|
| `go/parser` `go/ast` | 抽取 `templ Foo(...)` 签名;校验 `if`/`for`/`switch` 条件 | **不需要**。签名用"扫描到 depth-0 的 `{`"取原文;条件表达式直接抄进产物,交给 MoonBit 编译器 | 低 —— 反而更简单 |
| `io.Writer` | 组件写入目标 | `&Logger` trait(`write_string`/`write_char`/`write_view`),`StringBuilder` 已实现 | 无 |
| `context.Context` | 传 children / nonce / 已渲染 CSS 去重表 | **显式 `RenderCtx` struct**,不用隐式 context | 低 —— 见 §3.1 |
| `error` 返回 | 每次写入都可能失败 | `raise` effect(实测可用于函数类型与闭包);MVP 可先用不会失败的 `StringBuilder` | 低 |
| `sync.Pool` buffer 复用 | 性能 | 可省;MoonBit 侧 `StringBuilder` 足够 | 无 |
| 泛型 `stringable` 约束 | `{ expr }` 接受所有基本类型 | `[T : Show]` + `to_string()`。**实测 `String` 的 `Show::to_string()` 返回原文不带引号** | 无 |
| `go/scanner` 括号配平 | `{ expr }` 边界扫描 | 手写:跟踪 `()` `[]` `{}` 深度 + 跳过字符串/注释/rune | 中 —— templ 的 `expressionparser.go` 约 200 行可整体移植 |

**`context.Context` 是唯一需要改设计的地方。** Go 版本用 context 隐式传 children,好处是组件签名干净(`func hello(name string) templ.Component`,看不到 ctx)。MoonBit 没有 context,用显式 struct 反而更直白:

## 3. 已验证的设计(全部有实测证据)

以下原型均在本机 `moon 0.1.20261012` / `moonc v0.10.15` 上实际编译运行通过。

### 3.1 运行时设计(已落地于 `runtime/`,9 个单测通过、零警告)

```moonbit
///|
pub struct RenderCtx {
  children : Component
  nonce : String
}

///|
pub struct Component {
  priv render_fn : (RenderCtx, &Logger) -> Unit
}

///|
pub fn component(render : (RenderCtx, &Logger) -> Unit) -> Component {
  { render_fn: render, }
}

///|
pub fn Component::render(self : Component, ctx : RenderCtx, w : &Logger) -> Unit {
  (self.render_fn)(ctx, w)
}

///|
pub fn RenderCtx::with_children(self : RenderCtx, children : Component) -> RenderCtx {
  { children, nonce: self.nonce, }
}

///|
pub fn RenderCtx::clear_children(self : RenderCtx) -> RenderCtx {
  { children: Component::nop(), nonce: self.nonce, }
}

///|
pub fn Component::with_children(self : Component, children : Component) -> Component {
  component(fn(ctx, w) { self.render(ctx.with_children(children), w) })
}

///|
pub impl Show for Component with fn output(self, logger) {
  self.render(RenderCtx::new(), logger)
}

///|
pub extend Component with Show::{to_string, output}

///|
pub fn[T : Show] write_any(w : &Logger, v : T) -> Unit {
  write_escaped(w, v.to_string())
}
```

`impl Show for Component` 让 `.to_string()` / `println(html)` 免费可用。

**`clear_children` 是必需的,不是可选项。** 这一点在原型阶段没暴露,是 T1.1 写单测时才发现的:只在调用点 `with_children` 而不在组件体内清除,children 会**一路漏到所有后代组件**。templ 用 `ClearChildren(ctx)` 解决同一问题,生成的代码形状是「开头取出 children → 立即清空 ctx → 后面所有嵌套渲染都看不到 children」。单测 `children do not leak down to grandchildren` 锁住这个语义,生成器必须在每个组件体开头发射这两行(见 §3.2)。

**结构字段的两个约束**(实测):字段默认就是 public,写 `pub` 会报 `redundant_modifier` 警告,要私有必须写 `priv`;而记录字段不能当函数调用(`self.render(ctx, w)` 报 E4015),所以内部字段取名 `render_fn`,对外暴露 `Component::render` 方法 —— 这样生成代码里 `ctx.children.render(ctx, w)` 才是自然写法。

### 3.2 生成代码的形状(实测编译+渲染通过)

对这段 templ:

```templ
templ layout(title string) {
	<html><head><title>{ title }</title></head>
	<body>{ children... }</body></html>
}
```

生成的 MoonBit(实际运行结果与预期逐字节一致):

```moonbit
///|
pub fn layout(title : String) -> @rt.Component {
  @rt.component(fn(ctx, w) {
    let children = ctx.children
    let ctx = ctx.clear_children()
    w.write_string("<html><head><title>")
    @rt.write_any(w, title)
    w.write_string("</title></head><body>")
    children.render(ctx, w)
    w.write_string("</body></html>")
  })
}
```

开头两行对应 templ 的 `GetChildren` + `ClearChildren`,用来阻断 children 向孙组件泄漏(见 §3.1)。**但不能无脑照发** —— 发射规则取决于组件体内容,否则会撞上 `unused_value` 警告:

| 组件体含 | 发射内容 |
|---|---|
| `{ children... }` | `let children = ctx.children` + `let ctx = ctx.clear_children()`,正文用 `children.render(ctx, w)` |
| 无 `{ children... }`,但有嵌套组件调用 | 只发 `let ctx = ctx.clear_children()`(不绑定 `children`,避免未使用变量) |
| 两者都没有 | 整段前导都省掉 —— ctx 不会被传给任何人,清不清都一样 |

带 children 的调用点:`layout("Home").with_children(child).render(ctx, w)`

实测覆盖并通过:嵌套组件、children 传递、`for` 循环、HTML 转义、`String`/`Int`/`Double`/`Bool` 的泛型输出、跨包 import。

### 3.2.1 生成代码必须主动规避的 MoonBit 陷阱(实测踩到)

原型首轮编译出 4 类警告,这些**全部是 generator 必须自己处理的**,否则用户的构建会刷满警告:

| 警告 | 触发点 | generator 的应对 |
|---|---|---|
| `ambiguous_block` | 单字段 struct 字面量 `{ render }` 被判为歧义 | 生成时加尾逗号 `{ render, }` |
| `unused_value` | 嵌套闭包里没用到 `ctx`(如纯静态子组件) | 生成 `fn(_ctx, w)` |
| `unused_value` | children 前导里的 `let children = ctx.children`,但模板没用到它 | 按上表分级发射(见 §3.2);别为了图省事无脑照抄前导 |
| `implicit_impl_as_method` | runtime 里 `impl Show for Component` 的 `to_string`/`output` 被隐式提升,已废弃 | runtime 补 `pub extend Component with Show::{to_string, output}` |
| `deprecated` | `StringBuilder::new()` | 用 `StringBuilder()` |
| `unused_value` | **模板声明了但正文没用到的参数**(Go 只对局部变量报警,函数参数不报) | 正文开头 `ignore(x)`,见下 |
| `unused_value` | 正文不产生任何输出,写游标参数 `w` 没被用到 | 该参数直接命名 `_w` |

倒数第二条是 T2.9 实测新发现的:`templ foo(x : Int) { <p>hi</p> }` 生成出来的 `pub fn foo(x : Int)` 会因为 `x` 未被使用而报警。Go 只在函数体内报未使用的局部变量,参数不管,所以 templ 没有这个问题,照搬会踩到。候选对策有两条——正文开头发 `ignore(x)`,或把参数改名成 `_: Int`——**T2.16 定案选前者**:`ignore(x)` 保住具名调用(`foo(x=1)`)和签名可读性,而改名会把签名读成一堆 `_`,等于丢掉形参名字这个信息。定案时的两条补充判据:

- **判不准就当成"用到了"。** `ignore` 一个其实被用到的名字零代价,漏 `ignore` 一个没被用到的名字才留警告 —— 所以出错方向要偏保守,最坏是多一条警告,不会让体坏掉。
- **只对平凡标识符动手。** `~name` 这类带标签的参数、以及任何非标识符的形参一律跳过:调用点怎么拼是调用者的事,生成器不能替他改。

"正文有没有读这个参数"只在 `StringExpression` 里搜(元素递归下去),文本节点不算——`<p>name</p>` 里的 `name` 是给用户看的字,不是读参数;匹配还要按整词边界,否则参数 `a` 会被 `ab` 误判成已用。

最后一条是 T2.16 实测新发现的:`templ t() { { } }` 的正文一个输出都不产生,`w` 就没人碰。这里用 `_w` 而不是 `w` + `ignore(w)`,空体的产物因此能压成一行 `@rt.component(fn(_ctx, _w) {  })`。

这两条对 `moon-templ` 是个硬要求:**产物是给用户编译的,必须 warning-clean**。建议把"生成产物零警告"作为 CI 门禁(T5.4)。

### 3.3 构建集成:两套机制(均已实测)

`moon.pkg` 有**两套等价机制**,不能混用(混用会报错):

**① 新版 DSL:`rule` + `dev_build`(推荐)**

```
formatter(ignore: ["hello_templ.mbt"])
rule(name: "codegen", command: "moon-templ-gen -i $input -o $output")
dev_build(rule: "codegen", input: "hello.templ", output: "hello_templ.mbt")
```

**② 旧版:`options("pre-build": [...])`**

```json
options(
  "pre-build": [
    {
      "command": "moon-templ-gen -i $input -o $output",
      "input": "hello.templ",
      "output": "hello_templ.mbt",
    },
  ],
)
```

两套机制的契约**完全一致**(均已实测):

| 项 | 实测结果 |
|---|---|
| 工作目录 | **module 根目录**(不是 package 目录;官方文档说法与实际不符) |
| `$input` / `$output` | module 根相对的路径,如 `./g/gen.mbt` |
| `input` / `output` 声明路径 | **相对 package 目录** |
| 增量行为 | ✅ 输入不变 → **不重跑**;输入变了 → 重跑。等价于 templ 的 `-lazy` |
| 产物是否参与编译 | ✅ 是,`moonc` 命令行里能看到生成的 `.mbt` |
| `input` 用 glob | ❌ 报 `input ... missing` |
| `input` 用目录 `.` | ⚠️ **不报错但不可靠**:实测改了目录内已有模板的内容后**不会重跑**(目录 mtime 只对增删条目敏感)。**不要用** |
| `input` 用数组 | ✅ 接受,`$input $output` **空格拼接**展开 |
| `input` 指向不存在的文件 | ❌ 报 `input ... missing` |
| 产物放在 package 目录外 | ❌ 被拒绝 |
| `dev_build` 省略 `input` | ❌ 报 `data did not match any variant of untagged enum MoonPkgGenerate` |

**`formatter(ignore: [...])` 是配套项:** 把生成产物排除出 `moon fmt`。不过按 §6.1 的结论,生成侧的产物本来就是 `moon fmt` 的不动点,`moon fmt` 不会改动它,所以这条从"必需"降为"用户可选的额外保险" —— 真正该守的是产物格式本身,而不是把产物藏起来。

**⚠️ 唯一的 DX 痛点:** `input` 必须逐文件显式列出(不支持目录/glob,目录形式的行为不可靠)。每新增一个 `.templ` 都要改 `moon.pkg`。这是相对 templ 的实质性退步。

### 3.4 更简单的路线:独立 CLI + 提交产物(推荐作为主线)

关键事实:**任何放进包目录的 `.mbt` 都会被自动编译,不需要在任何地方声明。**

所以完全可以照搬 templ 自己的模型:

```bash
moon-templ generate ./...     # 扫目录,生成 foo.templ → foo_templ.mbt
git add '**/*_templ.mbt'      # 产物提交进仓库,和 templ 的 _templ.go 一样
moon build                    # 普通编译,零配置
```

这条路**完全绕开了 §3.3 的 `pre-build` 声明问题**,而且:
- 零构建配置
- 与 templ 用户的心智模型一致(产物可读、可 review、可提交)
- `moon-templ generate -watch .` 提供开发期热生成

`pre-build` 则作为**可选的**便利功能提供,适合不想提交产物的人。

| 能力 | 结论 |
|---|---|
| 递归 enum 做 AST | ✅ `pub enum Node { El(String, Array[Attr], Array[Node]) } derive(Debug)` |

### 3.6 空白归一化的确切规则(已用 748 组差分用例对齐)

templ 的空白处理没有写在文档里,只能从 `parser/v2` + `generator/generator.go` 反推。**不要靠猜**:下面的规则是把 templ 自己的 parser+generator 编成一个探针程序(见 §3.6.1),对同一批输入跑出产物字面量、再逐条对齐得到的。

templ 的机制是"**前一个节点吃掉它后面的空白**":能带尾随空白的节点(元素、文本、字符串表达式、组件调用)会把紧随其后的空白消耗成自己的 `TrailingSpace`(`None` / `Horizontal` / `Vertical`);只有在节点列表开头没人可吃时,空白才会变成一个 `Whitespace` 节点,而它在列表首尾会被 `stripLeadingAndTrailingWhitespace` 丢掉。生成时,只有"当前节点和下一个节点都是行内内容"才写出一个空格(`SpaceVertical` 也归一成一个空格)。

移植到 moon-templ(我们的 parser 把一整段文本收成一个 `Text` 节点,不像 templ 那样在换行处切断),等价规则是 —— 对每个 `Text` 的值切分成 `Literal` / `Gap` 两种片段:

| 片段 | 处理 |
|---|---|
| 行内(不含换行的)空白,且两侧在本段文本内都有非空白字符 | **原样保留**(`a   b` → `a   b`) |
| 文本节点开头的空白整段 | `Gap`(它属于上一个节点的尾随空白) |
| 含换行的空白,从**第一个换行**起到该段空白结束 | `Gap`;第一个换行**之前**的水平空白原样保留 |
| 输出时 `Gap` | 前后都是行内内容 → 一个空格;否则整个删掉(列表首尾天然删掉) |

行内内容 = `Text` / 字符串表达式 / 控制流 / 非块级元素;块级元素名单照抄 templ 的 `blockElements`(含 `td` `th` `tr` `br` `title` `style` `link` 这几个"为了排版当块级看"的)。

几条实测反例(都进了差分表),容易想当然写错:

| 输入 | templ 产物 | 说明 |
|---|---|---|
| `<div> text</div>` | `<div>text</div>` | 列表开头的空白被丢 |
| `<p>a  </p>` | `<p>a  </p>` | 文本**尾部**的水平空白原样保留 |
| `<p>a \n b</p>` | `<p>a  b</p>` | 换行前那个空格属于上一行,保留;换行起归一成第二个空格 |
| `<div>a <p>b</p></div>` | `<div>a <p>b</p></div>` | 空格在 `<p>` 前、属于文本值,保留(即使 `p` 是块级) |
| `<div><p>a</p> b</div>` | `<div><p>a</p>b</div>` | 空格在 `</p>` 后、算 `p` 的尾随空白,块级 → 丢 |
| `<span>a</span>  <span>b</span>` | `<span>a</span> <span>b</span>` | 独立空白节点无论多长都归一成一个空格 |

#### 3.6.1 差分测试怎么复现

`parser/whitespace_golden_test.mbt` 的 748 条断言不是手写的,是用临时 Go 探针跑 templ **自己的** `parser.ParseString` + `generator.Generate`、取 `GeneratorOutput.Literals` 拼起来生成的(注意 `escapeQuotes` 用的是 Go 源码转义,要 `strconv.Unquote` 还原成运行时值)。要重跑或扩充:建一个临时 module,`require github.com/a-h/templ v0.3.1070`,按上面的方式导出即可。这套办法在任何"行为只能靠反推"的地方都值得再用一次。

## 4. 语法映射表(templ → moon-templ)

嵌入的表达式语言必须是 **MoonBit** 而非 Go,所以部分语法要改写:

| templ(Go) | moon-templ(MoonBit) | 说明 |
|---|---|---|
| `templ hello(name string)` | `templ hello(name : String)` | 签名原文透传,只换类型语法 |
| `{ expr }` | 同 | → `write_any(w, expr)`,要求 `expr : Show` |
| `@pkg.Component()` | 同 | `@` 前需空白(照抄 ADR 0001) |
| `@layout("T") { ... }` | 同 | children 机制照抄 |
| `{ children... }` | 同 | → `ctx.children.render(ctx, w)` |
| `@templ.Raw("<b>x</b>")` | `@rt.raw("<b>x</b>")` | 唯一的非转义出口 |
| `if x { } else { }` | 同 | |
| `for i, v := range items { }` | `for v in items { }` | **必须改**:MoonBit 的 `for..in` |
| `for i := 0; i < n; i++ { }` | `for i = 0; i < n; i = i + 1 { }` | MoonBit C 风格 for 语法 |
| `switch v { case "a": }` | `match v { "a" => ... }` | **已拍板**:用 MoonBit 原生 `match`,不用 Go 风格 `switch`(见 §8) |
| `{{ x := 1 }}` | `{{ let x = 1 }}` | MoonBit 用 `let` |
| `package main` | **不需要** | MoonBit 的包由目录 + `moon.pkg` 决定,源文件无包声明 |
| `import (...)` | **不放在 .templ 里** | MoonBit 的 import 在 `moon.pkg`,生成代码用 `@alias.` |
| `css red() { ... }` | 同 | 可选,第二阶段 |
| `script onClick(msg string) { ... }` | 同 | 可选,第二阶段 |
| `{% ... %}`(v1) | 直接报错 | 不实现 |

**两条结构性简化**(相对 templ 更简单):
1. `.templ` 文件**没有 package 声明** —— MoonBit 的包由所在目录决定。
2. `.templ` 文件**没有 import 块** —— 依赖声明在 `moon.pkg`,生成代码引用 `@alias.xxx`。这意味着 `.templ` 文件比 templ 的对应物更干净。

文件名映射:`foo.templ` → `foo_templ.mbt`(同目录)。

## 5. 先例:justjavac/template

MoonBit 生态里**已经有人做了几乎一模一样的事**,值得重点参考 —— 它证明了整条链路可行。

| 项 | 内容 |
|---|---|
| 项目 | [justjavac/moonbit-template](https://github.com/justjavac/moonbit-template),v0.1.1,MIT |
| 模板语法 | **EJS/Sailfish 风格**,不是 templ 风格:`<%= expr %>` 转义、`<%- expr %>` 原始、`<%~ "partial.mtpl" %>` 引入、`<% if ... { %>` 控制流 |
| 数据绑定 | 用户在 `.mbt` 里声明 struct 并打 `#tpl.path("templates/x.mtpl")` 属性,生成 `impl @template.Render for X with render(self)` |
| 生成器 | **本身用 MoonBit 写**,`template_codegen/`:ast 5.4KB + parser 4.5KB + codegen 22KB = **约 32KB MoonBit 代码** |
| 构建集成 | `options("pre-build": [{ "command": "template_codegen --scan $input -o $output", "input": [...], "output": "tpl.generated.mbt" }])` |
| 运行时 | `escape_html`、`render_value`、`SafeHtml`、`safe_html`、过滤器 `trim`/`upper` |
| 多模板策略 | **一个包合并生成一个 `tpl.generated.mbt`**(多输入 → 单输出),正是为了绕开 §3.3 的逐文件声明问题 |

**与 templ 的关键差异:** justjavac 的方案是"模板绑定到 struct",templ 是"模板文件自带组件声明"。templ 的方案**自包含性更好**(不需要在 `.mbt` 里额外写 struct + 属性),推荐 `moon-templ` 走 templ 路线。

它同时也给出了 MoonBit 写解析器的惯用法参考:

```moonbit
pub(all) suberror ParseError {
  UnclosedTag(path~ : String, offset~ : Int)
} derive(Eq, Debug)

pub fn parse(path : String, source : String) -> @ast.Template raise ParseError {
  let nodes : Array[@ast.TemplateNode] = []
  for offset = 0; offset < source.length(); {
    let rest = source.unsafe_substring(start=offset, end=source.length())
    match rest.find("<%") { ... }
  } nobreak {
    @ast.template(path~, nodes~)
  }
}
```

## 6. 推荐架构

```
moon-templ/                      # 本仓库(monorepo,三个 module 或一个 module 三个包)
├── runtime/                     # 发布为 mooncakes 包 daqing/moon-templ/runtime
│   ├── component.mbt            #   Component / RenderCtx / component() / with_children
│   ├── escape.mbt               #   escape / write_any / raw
│   ├── attributes.mbt           #   Attributes / RenderAttributes / class / style / URL 白名单
│   └── cssclass.mbt             #   CSSClasses / KV / ComponentCSSClass / CSSID(SHA-256)
├── parser/                      # .templ → AST
│   ├── types.mbt                #   AST 定义(对标 templ parser/v2/types.go,1581 行)
│   ├── templatefile.mbt         #   文件级:切分 templ / css / script 块
│   ├── element.mbt              #   元素 + 属性(6 级优先级分派)
│   ├── expression.mbt           #   { expr } 花括号配平扫描器(含字符串/注释/rune)
│   ├── controlflow.mbt          #   if / for / match
│   └── whitespace.mbt           #   空白归一化
├── generator/                   # AST → MoonBit 源码
│   ├── rangewriter.mbt          #   两态写入:累积字面量 vs 写代码
│   ├── generator.mbt            #   主生成逻辑
│   └── literal.mbt              #   字符串字面量切分 + MoonBit 转义
├── cmd/main/                    # CLI:moon-templ generate / fmt / watch
└── docs/
```

**三个高杠杆设计,建议直接照搬 templ:**

1. **AST 节点自带 `Write(w, indent)`** —— 一套 AST 同时支撑 codegen / fmt / LSP。
2. **`RangeWriter` 两态写入** —— 累积字面量 vs 写代码,约 130 行,是 codegen 的骨架;字面量合并 + 全文件共享下标是性能与热重载的基础。
   - 已落地为 `generator/rangewriter.mbt`(T2.7)。**一处与 templ 的差异**:templ 把下标发进产物(`WriteString(buf, 2, "...")`),因为它的运行时靠下标在 watch 模式下从 `.templ` 源文件里换字符串;我们的 runtime 没有这层,所以产物只写 `w.write_string("...")`(与 §3.2 原型一致),下标改为**只记录在 `RangeWriter::literals()` 里**——`generator -lazy` 的文件级变更检测(T3.9)直接用这个数组。等到做 `--watch`(T5.3)时再把下标发进产物即可,反正产物本来就是重新生成的。
3. **`VarN` 全局唯一命名 + 私有前缀** —— templ 的 `7745c5c3` 前缀纯粹是避免与用户代码撞名,MoonBit 换自己的前缀即可(如 `mt_`)。

**两条 MoonBit 特有的实现建议:**

- **parser 用 `StringView` 解构式写法,别引入 combinator 库。** MoonBit 官方没有 parser combinator,社区包多因旧 `moon.mod.json` 格式已不可用。最地道的写法是:
  ```moonbit
  for view = src {
    match view {
      ['<', '%', '=', .. r] => { ...; continue r }
      rest => break rest
    }
  }
  ```
  消耗完直接返回剩余 view,不需要手工递增 `pos`,也不用 `has_prefix` + 算偏移。templ 的每节点一个独立 parser + 有序分派表的结构可以原样保留。
- **生成后调 `@fmt.format` 规范化。**(`moonbitlang/parser/fmt`)实测能把乱写的源码规范成标准格式并自动补 `///|` 块分隔,让产物读起来跟手写的一样。**但 T2.16 实测后决定不做,理由见 §6.1。**

### 6.1 产物格式化:T2.16 决定不内联 `@fmt.format`(实测)

原计划是生成后调 `moonbitlang/parser/fmt` 的 `@fmt.format(src)` 把产物规范一遍(templ 生成后调 `gofmt` 的对应物)。**T2.16 实测后否决了这条路**,依据如下(全部可复现):

1. 临时把 `moonbitlang/parser@0.4.5` 加进 `moon.mod`,`@fmt.format(产物)` 会把产物改成**另一种版式**:`@rt.component(` 的闭包参数独占一行并带尾逗号,文件开头多一个空行且挪到注释之前。
2. 把这份格式化结果落盘后再跑 `moon fmt`,**`moon fmt` 又把它改回我们现在的版式**;与产物逐字节 `diff`,完全一致。
3. 也就是说这条链上的 `@fmt.format` **比工具链里的 `moon fmt` 旧**,两版 formatter 对同一份源码的"标准格式"并不一致。内联它等于主动生成一个 `moon fmt` 立刻要重写的文件 —— 用户仓库里 `git diff` 全是噪音,而且会当场把 T2.15 的漂移护栏弄红(护栏比对的是逐字节相等)。
4. 附带成本:`moonbitlang/parser/fmt` 的 README 自标 "highly experimental and work in progress"(注释格式、空行感知两项状态未打勾),依赖树也不小(x、lexer、moon_config、async、prettyprinter)。

**采纳的判据因此换成"产物是 `moon fmt` 的不动点"**,而不是"产物经过某个 formatter"。这条不需要新依赖就能守:生成侧靠构造保证(见 §3.2.1 与 T2.15:元素嵌套不推语句层级,只有块才推),验证侧由 T2.15 的漂移护栏兜住 —— 产物一旦被 `moon fmt` 改写,护栏立刻变红。`///|` 块分隔由 `write_template` 自己发,实测 `moon fmt` 保持不变。

等 T3.x 引入 `if`/`for` 这些真正的嵌套块、靠构造维持不动点不再划算时,再回来评估内联 formatter(届时要先确认所用版本与工具链的 `moon fmt` 一致)。

## 8. 待决策点与风险

**设计决策(已于 2026-10-17 拍板,对应 TASKS.md 的 T0.1–T0.4):**

1. **控制流用 MoonBit 原生 `match`,不用 Go 风格的 `switch`。** 与 MoonBit 语法一致,且支持模式匹配与解构。代价:`.templ` 文件无法逐字复用 templ 的语法,迁移工具需改写这一部分。
2. **生成产物提交进仓库,照搬 templ 的 `_templ.go` 模式。** `moon-templ generate ./...` 生成后 `git add`,编译零配置。绕开了 `pre-build` 必须逐文件声明输入输出的 DX 痛点;`pre-build` 作为可选便利功能另行提供。
3. **错误模型:MVP 不带 `raise`。** 组件签名为 `(RenderCtx, &Logger) -> Unit`,`StringBuilder` 写入不会失败。关键收益是**可以 `impl Show for Component`**(`Show::output` 不允许 raise),`println(html)` / `.to_string()` 免费可用。流式写入(签名带 `raise`)作为后续演进,届时需放弃 `Show`。
4. **扩展名沿用 `.templ`。** 便于对照 templ.guide 文档、复用 golden 样例、迁移已有模板时文件名不变。与 Go 版 templ 同名带来的混淆风险可接受。

**主要风险:**

| 风险 | 说明 | 缓解 |
|---|---|---|
| `pre-build` 的逐文件声明 | 不支持目录/glob,目录形式行为不可靠,新增模板要改 `moon.pkg` —— **最大的 DX 退步** | 主线走"独立 CLI + 提交产物";或提供 `moon-templ sync` 自动改写 `moon.pkg` 的 `dev_build` 规则 |
| `moon fmt` 重排产物 | 每次格式化都改生成文件,git diff 变噪音 | 用 `formatter(ignore: [...])` 排除产物(实测有效) |
| 空白归一化 | templ 最复杂、最易错的部分(块级元素判定、`SpaceVertical`→单空格降级) | 移植 templ 的 golden 测试目录作为基线 |
| 表达式边界扫描 | `{ expr }` 要正确处理嵌套括号、字符串、注释、rune | 整体移植 `expressionparser.go`(约 200 行) |
| 无 `gofmt` 等价物 | templ 生成后调 `gofmt` 保证产物合法格式 | 已解决,但**不走 `@fmt.format`**:T2.16 实测 `moonbitlang/parser/fmt` 这版的版式与工具链 `moon fmt` 不一致(它格式化过的产物会被 `moon fmt` 再改回去),内联反而制造 diff 噪音。改为要求**产物是 `moon fmt` 的不动点**,由生成侧构造保证 + T2.15 的漂移护栏守(见 §6.1)。`formatter(ignore:)` 仍可作为用户侧的额外保险 |
| 生态差异 | MoonBit 无 `net/http`,渲染目标不是 HTTP handler | 聚焦 `String` / `&Logger` 输出,Web 集成留给上层框架 |

**未能确认的点:**

- templ 的 `{ expr, expr }` 多值语义(`JoinStringErrs` 变参)在 MoonBit 侧是否要支持 —— 建议 MVP 只支持单表达式。
- MoonBit 侧 `@rt.Component` 作为**递归结构**的嵌套深度性能;未压测。
- MoonBit 未来版本是否计划引入通用宏(当前 `macro` 只是保留字);若引入,架构可简化。

## 9. MoonBit 语言坑清单(codegen 与 runtime 必须知道的)

以下全部在本机实测踩到,直接影响实现:

| # | 坑 | 正确写法 |
|---|---|---|
| 1 | **没有 `MutArray`** | `The type MutArray is undefined`。`Array[T]` **本身就是可变的**,直接用 |
| 2 | **`Regex::string(s)` 是"字面量匹配"** | 不是"从字符串编译正则"!`Regex::string("[a-z]+")` 永远匹配不到 `abc`。要用 `Regex::Regex(p)` / `Regex::unsafe_from_string(p)` / `re"..."` |
| 3 | **`Regex` 不支持 `\d \s \w`** | 改用 POSIX 类 `[[:digit:]]` `[[:space:]]` `[[:word:]]`;`.` 匹配换行;`^$` 是整串锚点;量词上限 256 |
| 4 | **范围模式必须写 `..<=`** | `'a'..'z'` 报 E3801,要写 `'a'..<='z'` |
| 5 | **enum/struct 跨包必须 `pub(all)`** | 只写 `pub` 报 E4036 `Cannot create values of the read-only type`。**AST 包对外必须用 `pub(all) enum`** |
| 6 | **递归函数必须显式写返回类型** | 否则报 E4074。parser 里每个递归函数都要标注 |
| 7 | **`String::escape()` 自带首尾双引号** | 生成字符串字面量时**不要再包一层**,否则变成 `""a\"b""` |
| 8 | **`@strconv.parse_int` 不存在** | 在 `moonbitlang/core/string` 的 `@string.parse_int` |
| 9 | **`Debug` ≠ `Show`** | 只 `derive(Debug)` 调 `.to_string()` 报 `no method to_string`,要额外加 `Show` |
| 10 | **`local` 是保留字** | 会触发 `reserved_keyword` 警告,换名 |
| 11 | **泛型函数语法** | 是 `pub fn[T : Show] name(...)`,**不是** `fn name[T](...)` |
| 12 | **`re"..."` 里别写 `\{`** | 与插值语法冲突,还会级联出假的 E4171,用 `re"^[{]"` |
| 13 | **`Array` 的 `+` 不拷贝** | 作用域叠加要用 `arr.copy()` 再 `push`,不是 `arr + [x]` |
| 14 | **`fn main` 不能 raise** | 报 E4122,写 `fn main raise` 或 `fn main { try! ... }` |
| 15 | **测试依赖要单独声明** | `import { ... } for "test"` / `for "wbtest"`,否则测试里 `Package "fs" not found` |
| 16 | **包别名是路径最后一段** | 导入 `"x/multi/lib"` 用 `@lib`,不是 `@multi/lib` |
| 17 | **argv[0] 是构建产物路径** | 真实参数从 `args[1]` 开始 |
| 18 | **默认 target 是 wasm** | `moon.mod` 里 `preferred_target = "wasm"`。好消息:实测 `@fs` / `@env` **在 wasm 下都正常工作**,CLI 不必强制切 native |
| 19 | **旧 `moon.mod.json` 格式的包已不可用** | 报 `no longer supported. Run moon fmt to migrate`。选依赖前先确认迁移状态(实测 `illusory0x0/simple_parserc`、`moonbit-community/XMLParser` 因此不可用) |
| 20 | **没有 parser combinator 官方库** | 推荐 `StringView` 解构式写法:`for view = src { match view { ['<','%','=', .. r] => ... } }` —— 消耗完直接返回剩余 view,无需手工递增 `pos` |
| 21 | **struct 字段默认就是 public** | 字段上再写 `pub` 报 `redundant_modifier` 警告;要私有必须写 `priv`。**产物要求 warning-clean,生成器定义 struct 时必须知道这条** |
| 22 | **记录字段不能当函数调用** | `self.render(ctx, w)` 报 E4015 `Type Component has no method render`,提示改用 `(self.render)(...)`。故 runtime 采用 `priv render_fn` 字段 + `Component::render` 真方法 —— 这样生成代码里 `ctx.children.render(ctx, w)` 才是自然写法,不必到处写括号 |
| 23 | **`moon info` 的产物是 `pkg.generated.mbti`** | 不是旧约定的 `<包名>.mbti`。找接口文件时别找错名字 |
| 24 | **`derive(Debug, Eq)` 会触发 `implicit_impl_as_method` 警告** | 每个类型要为每个 derive 的 trait 补显式 `extend`:`pub extend Node with Eq::{equal, not_equal}`、`pub extend Node with @moonbitlang/core/debug.Debug::{to_repr}`。另外凡引用 `@moonbitlang/core/debug` 就必须在 `moon.pkg` 里 `import { "moonbitlang/core/debug" }`,否则报 `core_package_not_imported`。**5 个类型 = 10 条 extend,是本项目定义公开类型的固定成本** |
| 25 | **struct 构造用字面量语法,不是构造器** | `Element(name="div", ...)` 报 E4085;要写 `let e : @pkg.Element = { name: "div", ... }`。带 `~` 标签的只有 **enum 构造器**(如 `Constant(name=..., value=...)`) |
